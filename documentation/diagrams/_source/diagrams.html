Diagram 01 · Website architecture

Three files, no build step, one request graph.

Everything the browser executes is authored by hand and served as-is. There is no bundler, no transpiler, no package manifest and no node_modules: what is in the repository is byte-for-byte what reaches the visitor.

What each file owns

index.html Eleven <section> elements, one per layer, plus the drawing register, the opening shell and the title block. Carries the full alt text for all twelve drawings and an inline pre-paint script that decides whether the opening runs. Structure
style.css Ten numbered parts: tokens, reset, type, layout, cinema, sections, plates, motion, responsive, print. All colour, spacing, type and motion is declared as custom properties on :root and read from there. Presentation
script.js One IIFE, nine independent modules held in a registry and started inside individual try/catch blocks, so a fault in one cannot take down the rest. Behaviour
assets/draw/ Seven engineering plates at one true 30° isometric, each shipped at 1× and 2× as WebP and selected by srcset. Five detail vignettes carry the sustainability schedule. Drawings
assets/fonts/ Two self-hosted variable WebFonts, preloaded from the document head. Self-hosting is what removes the last third-party origin from the page. Type
assets/video/ One short operations clip in two containers with a poster frame. preload="none", started by observer only when Layer 06 is approached. Ground

Diagram 03 · User journey

What the reader is asking at each depth, and what the page answers with.

Three audiences share one scroll: a prospective tenant checking whether the capacity is real, a lender checking whether the programme is bankable, and an engineer checking whether the people drawing it know what they are doing. The descent answers all three in the same order.

Wayfinding is available at every depth

Always on screenThe title block The fixed bar names the layer the viewport's midline is currently inside, and takes that layer's trade colour. It is the drawing's corner block, not a nav menu.
One press awayThe drawing register Ten rows, each with its trade colour as a rule and its drawing number on the right. Layers with no plate say "No plate" rather than being omitted.
ContinuousThe depth rule A single hairline under the bar, scaled to scroll progress and tinted to the current trade. Depth replaces a permanent nine-item index in the margin.

Diagram 05 · Colour system

On an engineering drawing a colour means a state. Here it means one too.

Monochrome carries the whole page. One accent appears only where something is energised, current or under the cursor. Diagram 07 · Runtime modules

Nine modules, started independently, each with a stated failure state.

They were nine bare calls in a row once, which meant a throw anywhere took out every module after it — a fault in the WebGL field was enough to stop the headline turning, silently. They are now iterated from a registry inside individual try/catch blocks, and the registry is audited at load so a missing function is reported rather than swallowed.

Principle 01Position drives behaviour Anything triggered by where the reader is uses IntersectionObserver. There are six. The single scroll listener that remains is rAF-coalesced, passive, writes one custom property, and does not bind at all where the CSS scroll timeline is supported.
Principle 02Degrade to the finished page Every module's failure state is a working static page. Nothing hides itself until JavaScript has proven it can bring it back.
Principle 03Motion is CSS, not JS prefers-reduced-motion is honoured in the stylesheet. JavaScript consults it only where it would otherwise start a loop — the WebGL field, the video and the turning word.

Four breakpoints, and each one changes a composition rather than a size.

Preference queries — three, and each one changes behaviour rather than removing it

prefers-reduced-motionGentler, not silent Transform and position are stripped; colour and opacity feedback keeps its authored timing, because press feedback is not what causes discomfort — movement is. The video is replaced by its own poster frame, and the headline still turns, crossfading in place, because the word carries meaning rather than decoration.
prefers-reduced-transparencyOpaque chrome The bar's 97% white becomes solid white when the reader has asked for less translucency.
printA4 landscape drawing set One layer per sheet, the bar relocated into the bottom margin as a repeating title block, the dark section printed on white, and every revealed element forced visible — which also fixes a real defect, since printing on load would otherwise produce a near-blank document.

Diagram 10 · Image and asset pipeline

Optimised once, at authoring time, and then never again.

With no build step and no image CDN, every optimisation has to be baked into the committed artefact. The master renders — 5.0 to 7.6 MB PNGs — stay in the repository as working material and are excluded from what is served.

7 plates · 5 vignettes

01 · AuthorMaster render PNG at 3,000–4,000 px, 5.0–7.6 MB each. True 30° isometric, one line weight family, one neutral ramp, trade colour applied per system. assets/draw/_src/ · git-ignored from the served tree
02 · EncodeWebP, two densities 1× at 1,200–2,000 px and 2× at 2,400–4,000 px. The shipped plate drops from ~7 MB to 81–216 KB — a 96–98% reduction with no visible loss on line art. 81 KB – 216 KB per plate
03 · Declaresrcset + sizes Intrinsic width and height on every image so the box is reserved before the bytes arrive and the layout never shifts. sizes states the real column: 52 vw above 860 px, 100 vw below. CLS contribution: none
04 · Deferlazy + async loading="lazy" and decoding="async" on all twelve drawings, so only the plates near the viewport are fetched. Eight of the nineteen requests never happen for a reader who does not scroll. 8 requests · 607 KB on first view
05 · ServeStatic origin One origin, no transform service, no signed URLs. The browser picks the density; the server does nothing but send bytes and set cache headers. 19 requests · 2,019 KB complete
FontsTwo files, preloaded Variable WOFF2, self-hosted, rel=preload in the head and font-display: swap. 113.6 KB covers every weight and width the page uses.
VideoWebM first, MP4 fallback 413 KB and 448 KB. Only one is ever fetched — measurement confirms WebM wins and MP4 is never requested by a modern browser.
FaviconInline data URI The mark is the plan of one hall on the isometric, written as an SVG data URI in the head. Costs no request and survives every size the browser asks for.

Diagram 11 · Deployment architecture

Author → commit → upload → serve. There is no build stage to fail.

Because the repository contains the finished artefact, deployment is a file copy and rollback is a file copy in the other direction. This is what removes the entire class of deployment failures that dominate framework-based sites.

Hostinger · shared or business

LocalAuthor Edit index.html, style.css, script.js. Open the file directly — the site runs from file:// with no server at all.
gitCommit The commit is the release. Working material — master renders, candidates, the archive — is git-ignored and never reaches the host.
TransferDeploy hPanel Git deploy, or SFTP, or the File Manager. Target is public_html/. Roughly 6.5 MB, one directory.
OriginLiteSpeed Serves static files, terminates TLS, applies the .htaccess cache and compression rules. No PHP process is involved in any request.
EdgeCDN + browser Immutable one-year cache on hashed-by-content assets, short revalidation on the three source files. Repeat views cost one conditional request.

What is not in this diagram, and why that matters

AbsentNode runtime Nothing executes on the server. Shared hosting is therefore sufficient, not a compromise.
AbsentBuild step No install, no compile, no cache to warm. A deploy cannot fail because a transitive dependency changed.
AbsentEnvironment variables No secrets exist. There is nothing to leak into a client bundle and nothing to configure per environment.
AbsentDatabase No backup strategy beyond the files themselves, and no migration to get wrong.
AbsentAPI surface The only outbound action on the page is a mailto: link. The attack surface is the file server.

Rollback

Mechanism
git checkout <previous tag> and re-upload, or restore the previous public_html from a Hostinger snapshot. Both are complete: there is no partially migrated state a static site can be left in.
Time to restore
Under two minutes by file transfer; under ten by panel snapshot.
Blast radius
One directory. No dependent service, no queue to drain, no cache to invalidate beyond the CDN purge.
